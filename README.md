# Korea Lyrics Translator｜韓語歌詞詞源標註

[開啟網站](https://smartleo123.github.io/Korea-Lyrics-Translator/)

貼上韓文歌詞或搜尋歌名／歌手，自動標註漢字詞、固有詞與外來語，並可切換顯示逐行繁體中文譯文。保留貼上的換行、空行與原有段落，支援點擊修正詞義、下載獨立 HTML 與直接下載 PDF。

## 歌曲搜尋（LRCLIB）

為了簡化操作並避免 先前資料來源的 503 和多份曲目清單，網站已恢復最初的 **LRCLIB 單一搜尋方案**：

- 輸入歌名後查找相關版本；可加上歌手名稱縮小結果。
- 輸入歌手名稱後查找相關歌曲，同名錄音版本會合併顯示，必要時選擇版本。
- 選擇「帶入歌詞」後會檢查內容是否含有韓文原詞；英文或羅馬拼音歌詞不會覆蓋原本貼上的歌詞。
- 原本自行貼上韓文歌詞的功能完全保留。

**限制：** LRCLIB 公開搜尋單次最多回傳約 20 筆結果，沒有完整歌手作品清單的分頁介面。此版本以搜尋簡單、直接取得歌詞為優先，不會宣稱可列出所有歌曲。LRCLIB 來源：[lrclib.net](https://lrclib.net/)。

## 上下文優先的標註流程（2026-11 修正版）

1. **先取得整句繁體中文**：優先使用使用者提供的中文，否則使用 MyMemory 翻譯每行韓文並快取。
2. **Garu 斷詞及詞源分類**：原文不修改；漢字詞源只由韓語詞典／形態分析決定，不能根據中文逆推。
3. **句子差異對位（新）**：對最多 12 個優先候選詞，嘗試將該韓文詞從原句移除，再由同一翻譯服務翻譯一次，比較兩份中文的共同前後文。只有其餘句子翻譯足夠穩定、差異清晰時，才把差異片語用作該詞的語境意思。**不是針對歌曲建立固定翻譯表**，也不會在對位不成立時自行猜測意思。
4. **詞典與未對位詞彙補譯**：保留原有詞典及 MyMemory 單字補譯，避免大量漏標。單字補譯的快取改成「韓文單字＋原始歌詞句子」共同索引，避免先前歌曲的錯誤意思污染新的歌詞；原本的舊單字快取不再沿用。
5. **分開呈現漢字與語意**：例如能可靠對位的漢字詞顯示「漢字寫法 · 語境中文」，不把漢字字形誤認為歌詞中唯一的意思。最後才一次輸出原文、註解及可切換的逐行中文譯文，HTML／PDF／全螢幕閱讀同步支援。

**限制與效能**：MyMemory 不支援真正的逐詞對齊；差異對位是基於兩份翻譯的穩定性判斷，不是具備語意理解的模型。句子刪詞後的翻譯有可能不穩定，這時不強行套用；仍可能有不準確的詞典或單字機譯。每次新增的對比翻譯最多 12 筆，會增加第一次處理歌詞的時間並受到免費 API 額度限制；已完成的對位快取於本機。若使用者自行修改詞義，以其修改為優先。

## 韓文標註與翻譯

- [Garu](https://github.com/ongjin/garu) WebAssembly 形態分析，在瀏覽器裡辨識詞性、部分語尾與助詞。
- [HanjaHanja Dictionary](https://github.com/ongocompany/hanjahanja-dict) 漢字詞資料，提供數萬個韓語漢字詞條。對同音不同義詞保留候選，部分詞依保守上下文規則協助選字。
- 常用固有詞／口語活用詞提供繁體中文釋義；缺漏時預設嘗試免費 MyMemory API 補譯。翻譯有快取、速率限制、請求超時及失敗中止機制，機譯仍可能不準確。
- 紅色為漢字詞、白色為固有詞、紫色為外來語。詞旁註解直接顯示；不顯示「待確認」或 `≈` 字樣，但不表示所有詞都有可靠詞義。
- 結果區右上角可切換逐行中文翻譯。若你有可合法使用的官方中文譯文，可以自行貼上優先使用；沒有提供的行再嘗試 MyMemory。**網站不會宣稱機器翻譯是官方譯文**。
- 結果可點擊校正，修改後的詞義儲存在此瀏覽器的本機資料中；已移除詞庫檔案匯入／匯出按鈕。翻譯中文字會傳送至第三方服務，請勿貼入敏感內容。

## 全螢幕歌詞閱讀

標註完成後，可在右側結果區按「⛶ 全螢幕閱讀」，將韓文歌詞與詞源註解以 30px 大字在全視窗閱讀。A＋／A− 可調整 20–54px 字體大小並記住瀏覽器偏好；原始分段、詞源顏色與已顯示的逐行中文翻譯會一同呈現。按 Esc 或「退出全螢幕」回到編輯頁面。此閱讀模式採用全視窗對話框，不會更改原本的字體大小或歌詞內容。

## PDF 匯出

結果區新增「下載 PDF」，在瀏覽器本機以 html2pdf.js 產生檔案，保留韓文詞源註解、顏色、段落與可選的逐行中文翻譯；無需另外上傳至 PDF 服務。PDF 以高解析度畫面渲染，因此內容主要以圖片方式保留，不等同可搜尋或選取文字的 PDF。若需要可複製的純文字，可使用 HTML 下載或「複製標註文字」。

## Garu 詞幹查詢與保守語境翻譯

Garu 詞幹只在詞性與詞幹資訊完整、且詞典確實收錄詞條時，才以基本形（動詞／形容詞 + 다；名詞保留原詞根）查找中文詞義。該查詢不改動歌詞原字形、漢字詞源或人工修正。缺乏完整形態資訊時不猜測活用規則。刪詞重翻僅在完整句子譯文差異極小且原詞沒有任何詞義時才用來補缺；不會覆蓋人工、詞典或其他已知註解。每次最多執行 4 筆此類比對，並使用新版快取隔離舊的不可靠結果。

### 開源韓中詞典（無 API Key）

當 Garu / 內建詞典沒有取得中文詞義時，網站按需讀取 [basickorean-vocab](https://github.com/basickorean/basickorean-vocab) 依韓文首字拆分的中文詞典 shard。該資料出自韓國國立國語院「韓國語基礎詞典」，採 [CC BY-SA 2.0 KR](https://creativecommons.org/licenses/by-sa/2.0/kr/) 授權；本專案保留署名並不將資料混成私有詞庫。遠端 shard 版本固定為 `01516acf2c5c9796e3ccfe2b89b1d75a7536b5a1`，避免無預警變更。詞典「簡體中文」以 opencc-js 轉為臺灣繁體，僅取單一無歧義的簡短詞義。多義或資料不可用時不強行猜測，使用者詞義／可靠漢字詞源永遠優先。外部詞典需要網路，但不需要 API Key 或 AI 模型；若 CDN 無法連線則回退到既有流程。

### 2026-11：詞典覆蓋率與可靠性改善

1. 外部韓中詞典不再默默截斷前 32 個首音節分片；提供可選 `maxShards` 預算時，結果明確回報 `skippedShards`。
2. 以限量 LRU 形式保留近期查過的詞典分片，重複歌詞共享同一下載；錯誤下載不永久快取。
3. 移除執行流程中以「刪掉一個韓文詞後重翻整句」推定單字中文的策略，減少誤標與額外免費 API 呼叫。此策略的單元測試仍可作為研究用途，不再參與正式標註。
4. 在原本的狀態列顯示「開源詞典補充」與「未標註」數量，統計以實際可見的中文為準。單字詞典詞義與完整句子機譯仍屬不同證據，不會混用為漢字詞源。

5. 多義詞若只有 2–3 個短而可讀的詞典義項，將各義項以「／」分隔顯示，讓學習者看見有來源的替代詞義；超過 3 個義項或內容過長則保守留空。這不是逐句 AI 對齊，也不自動選出某一個義項。

### 單詞只顯示單一詞義（2026-11）

新詞義選擇器會從有來源的繁體中文詞典義項，依「整句中文包含完整詞義 → 中文雙字重疊 → 詞典既有排序」挑選一個結果；不呼叫任何 AI API，也不再以「／」堆疊多個義項。人工修正與真正的漢字字形原樣保留。這是一種規則式機率近似，不能保證每次都能選到語境最合適的翻譯。Garu 可辨認的複合名詞與助詞也會合併查詞，減少沒有標註的韓文。

### 有詞典佐證的活用詞補查

對尚無中文詞義的動詞／形容詞，以及極少數具有「受詞＋疑似活用詞」證據的漢字同音詞，會按需查詢韓國語基礎詞典 `shards/core` 中的真實 `fm` 活用清單，再讀取已收錄的中文基本形。只有語境譯文與動詞義項相符，才可能把原本誤判的漢字名詞改標為固有詞。此處不是 AI 對齊，也不會合成任意韓文動詞詞形。外部詞典若無資料，保留原本標註。

### 2026-11 韓語文法誤標防護

先以 Garu 的詞性證據辨識口語代名詞縮約、否定副詞與依存名詞（例如 NP、MAG、NNB 等）。僅在辨識到相關文法或受詞修飾結構時，才優先於一般漢字／名詞詞典，避免將語法詞誤譯為同音的實物名詞；人工更正保持最高優先。不對歌曲建立固定答案表，也不使用外部 AI 對齊服務。整句翻譯的 MyMemory 品質仍是獨立限制，不能靠規則式詞彙比對保證句義正確。

## 免費整句翻譯來源與測試集

新增「啟用免費瀏覽器翻譯」：在支援的桌面 Chrome / Edge 上使用原生 `Translator`（韓文 `ko` → 繁體中文 `zh-Hant`）。瀏覽器可能下載語言包；不支援或模型輸出不合格時回退 MyMemory。不需要 API Key，不是額外的 AI 詞組對齊介面，原有詞典及手動譯文仍優先。不同來源的快取相互隔離，避免舊的 MyMemory 錯譯遮蔽瀏覽器翻譯。

`benchmark/translation-cases.json` 保存 16 筆短的人工參考譯文與常見錯誤檢查點；`translation-evaluation.js` 是離線品質冒煙測試，不把答案寫進生產翻譯程式。這些關鍵字覆蓋率和禁用錯詞命中率不是 BLEU、COMET、人工評分，也不代表任何翻譯服務的實測準確率。評估實際翻譯來源需要先生成它的輸出再評分；沒有真實模型輸出不能聲稱效果提升。

### 利用詞典釋義消除多義誤判

中文詞典每個義項通常同時含有簡短標籤與完整解釋；單詞選義現在除了比對標籤，也會比對釋義與整句中文，改善如「清晰」與「聰慧」這類不同義項的語境判定。這是詞典證據排序，不是模型機率或硬編碼歌曲翻譯；若沒有語境證據仍依詞典次序。另以詞性證據區分韓語所有格限定詞（例如第一人稱「我的」）與名詞同形詞。
